# Paired batch execution

## Run matrix

One batch contains a single graph stratum: all graphs must share `node_count`, `readout_node`, and
`max_rounds`. The immutable run key is:

```text
task x graph x experiment_seed x assignment_seed x condition
```

Each combination contains one clean condition. When attacks are enabled, it additionally contains
one condition for every non-readout attack node. An `n`-node graph therefore contributes exactly `n`
traces per task, experiment seed, and assignment seed. Clean runs are not duplicated for every
attack location.

`experiment_seed` selects cached independent Round-zero responses and later replica-round stochastic
streams. `assignment_seed` selects a graph-independent permutation from replica slots to structural
nodes. Both dimensions are explicit so initial generation noise and initial-state placement can be
paired or averaged separately.

## Preflight

The runner performs all checks before its first uncached inference request:

- task IDs and graph IDs are unique;
- the graph collection is one fixed stratum;
- every `(task, experiment_seed, replica_slot)` record exists exactly once;
- Round-zero and post-cache execution use the same prompt and pinned model identity;
- every attacked task has one Oracle-accepted adversarial answer;
- the selected mutation remains eligible under its persisted objective and plausibility verdicts;
- readout is excluded from the attack positions.

No missing mutation is replaced with a lower-quality candidate, and no incomplete Round-zero cache is
silently regenerated by this module.

## Artifacts and recovery

```text
<output-dir>/
|-- manifest.json
|-- plan.jsonl
|-- inputs/
|   |-- tasks.jsonl
|   |-- graphs.jsonl
|   |-- round_zero_index.jsonl
|   `-- adversarial_answers.jsonl
|-- outcomes.json
|-- summary.json
`-- traces/
    `-- <run_spec_id>.json
```

The manifest fingerprints the tasks, graphs, selected Round-zero records, selected adversarial
answers, execution settings, prompt version, model identity, and complete plan. The `inputs/`
directory makes the batch self-contained for later analysis. It stores exact task and graph
snapshots, selected adversarial answers, and compact references to the immutable Round-zero cache
records. The complete cached text is replayed into each trace at Round zero. `plan.jsonl` lists every
expected run cell before execution starts.

Each trace is written atomically and contains its run spec plus a full SHA-256 trace fingerprint. On
resume, a matching trace is reused; a missing trace is executed; a malformed, tampered, or
identity-mismatched trace stops the batch. Summary and outcome files are regenerated atomically after
the complete plan finishes.

`trace_model_calls` counts logical node transitions represented by all completed traces. When exact
state replay is disabled, every logical transition is one backend inference. When it is enabled,
`trace_backend_calls` counts physical model inferences and `state_replay_cache_hits` counts logical
transitions served by replay. `new_model_calls` retains its historical field name but counts physical
backend calls made for traces generated during the current invocation. A fully cached trace resume
therefore reports the original trace cost but zero new calls.

## Exact state-consistent replay

The optional `state-consistent-replay-v1` policy implements common random numbers for paired
counterfactual execution. It defines the model transition at an exact local state and exact
stochastic stream once, then replays that realized output when another clean/attack/topology run
reaches the same state with the same seed. This deliberately changes the protocol from independent
resampling; it is not justified by assuming that a second model call would return similar text.

The cache identity includes:

- the complete ordered chat messages;
- generation seed, temperature, and maximum output tokens;
- requested and expected-returned model identity;
- an operator-supplied 64-character model-content fingerprint;
- prompt version and an experiment namespace.

Run IDs are deliberately excluded, because paired run labels are not part of the model state.
Different experiment seeds, messages, decoding settings, prompts, model fingerprints, or namespaces
cannot share an entry. There is no embedding, semantic-similarity, parsed-answer, or prefix match.

Entries are immutable and SHA-256 checked. Within one process, concurrent identical requests use
single-flight execution. Across processes, duplicate computation may occur during a race, but atomic
first-writer publication selects one complete result and all readers subsequently replay it. A
manifest mismatch or modified entry fails closed.

Enable it only for a new batch protocol and a new output directory:

```powershell
--state-replay-cache-dir runs/state-replay/pilot-v1 `
--state-replay-model-fingerprint <64-character-sha256> `
--state-replay-namespace llama31-8b-pilot-v1
```

The fingerprint must identify the immutable local model artifact, not merely a mutable model alias.
The runner records the replay policy and identity in the batch manifest. Batch protocol v3 prevents
older independently resampled traces from being silently mixed with replay traces.

## CLI

```powershell
topology-mas-run-batch `
  --tasks data/prepared/gsm8k/main.jsonl `
  --graphs data/prepared/graphs-v2/n5_m8_t3_seed0/graphs.jsonl `
  --round-zero-dir runs/round-zero/pilot-v1 `
  --mutations-dir runs/mutations/pilot-v1 `
  --output-dir runs/execution/n5_m8_t3 `
  --experiment-seeds 0,1,2 `
  --assignment-seeds 0,1,2 `
  --model deepseek-chat `
  --expected-returned-model deepseek-v4-flash `
  --base-url https://api.ohmygpt.com/v1 `
  --api-key-env OHMYGPT_API_KEY
```

Use `--clean-only` to omit attacks; then `--mutations-dir` is not required.

## Paired analysis

```powershell
topology-mas-analyze-batch `
  --batch-dir runs/execution/n5_m8_t3 `
  --output-dir runs/execution/n5_m8_t3/analysis-v1
```

The analyzer refuses incomplete plans, missing or extra traces, fingerprint mismatches, and older
non-self-contained batch versions. It writes one row per run, one row per clean/attack pair, graph
metrics in JSON and CSV, and `classical_initial_states.jsonl` for later DeGroot, voter, or other
non-LLM dynamics baselines.

For graph `G`, `U` is clean final accuracy, `A_i` is attack accuracy when node `i` is controlled,
`R_mean` is the mean of `A_i`, `R_worst` is the minimum `A_i`, `D_i` is the paired clean-minus-attack
accuracy difference, and `D_max` is the maximum node-level `D_i`. These are point estimates, not
significance claims.

Target propagation uses paired clean/attack comparisons. A non-attacker state is counted as
*induced* only
when it matches the target error in the attack trace but the same node and round does not match it
in the paired clean trace. This prevents a coincidental independent occurrence of the same wrong
answer from being mislabeled as infection.

## Interpretation boundary

Completeness, resume safety, and identity checks are implementation properties. They do not establish
that a model is robust or that two topologies differ. The real-model smoke only verifies that the
artifact pipeline reaches the pinned provider model and produces auditable traces.
