# Paired batch execution

## Run matrix

One batch contains a single graph stratum: all graphs must share `node_count`, `readout_node`, and
`max_rounds`. The immutable run key is:

```text
task x graph x experiment_seed x assignment_seed x condition
```

Each combination contains one clean condition. When attacks are enabled, it additionally contains
one condition for every non-readout attack node. An `n`-node graph therefore contributes exactly `n`
traces per task, experiment seed, and assignment seed. Clean runs are not duplicated for every
attack location.

`experiment_seed` selects cached independent Round-zero responses and later replica-round stochastic
streams. `assignment_seed` selects a graph-independent permutation from replica slots to structural
nodes. Both dimensions are explicit so initial generation noise and initial-state placement can be
paired or averaged separately.

## Preflight

The runner performs all checks before its first online model call:

- task IDs and graph IDs are unique;
- the graph collection is one fixed stratum;
- every `(task, experiment_seed, replica_slot)` record exists exactly once;
- Round-zero and online execution use the same prompt and pinned model identity;
- every attacked task has one Oracle-accepted adversarial answer;
- the selected mutation remains eligible under its persisted objective and plausibility verdicts;
- readout is excluded from the attack positions.

No missing mutation is replaced with a lower-quality candidate, and no incomplete Round-zero cache is
silently regenerated by this module.

## Artifacts and recovery

```text
<output-dir>/
|-- manifest.json
|-- plan.jsonl
|-- outcomes.json
|-- summary.json
`-- traces/
    `-- <run_spec_id>.json
```

The manifest fingerprints the tasks, graphs, selected Round-zero records, selected adversarial
answers, execution settings, prompt version, model identity, and complete plan. `plan.jsonl` lists
every expected run cell before execution starts.

Each trace is written atomically and contains its run spec plus a full SHA-256 trace fingerprint. On
resume, a matching trace is reused; a missing trace is executed; a malformed, tampered, or
identity-mismatched trace stops the batch. Summary and outcome files are regenerated atomically after
the complete plan finishes.

`trace_model_calls` counts the online calls represented by all completed traces. `new_model_calls`
counts calls represented by traces generated during the current invocation. A fully cached resume
therefore reports the original trace cost but zero new calls.

## CLI

```powershell
topology-mas-run-batch `
  --tasks data/prepared/gsm8k/main.jsonl `
  --graphs data/prepared/graphs-v2/n5_m8_t3_seed0/graphs.jsonl `
  --round-zero-dir runs/round-zero/pilot-v1 `
  --mutations-dir runs/mutations/pilot-v1 `
  --output-dir runs/execution/n5_m8_t3 `
  --experiment-seeds 0,1,2 `
  --assignment-seeds 0,1,2 `
  --model deepseek-chat `
  --expected-returned-model deepseek-v4-flash `
  --base-url https://api.ohmygpt.com/v1 `
  --api-key-env OHMYGPT_API_KEY
```

Use `--clean-only` to omit attacks; then `--mutations-dir` is not required.

## Interpretation boundary

Completeness, resume safety, and identity checks are implementation properties. They do not establish
that a model is robust or that two topologies differ. The real-model smoke only verifies that the
artifact pipeline reaches the pinned provider model and produces auditable traces.
